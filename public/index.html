Windows 11 · NVIDIA GPU · loopback-only by design

Your own private AI, running on your own PC.

AFK-LocalAI is a self-hosted, ChatGPT-style workspace for Windows: a chat UI, a private web-search engine, and local voice, with models served by Ollama on your own GPU. Nothing leaves your PC unless you explicitly turn it on. Install with one double-click.

Repo:allusionsafk/localai-windows-starter
What you get
  • Chat UI: Open WebUI at localhost:3000
  • Private web search: SearXNG at localhost:8080
  • Local voice: Kokoro TTS + Whisper, CPU-only
  • Local images: optional ComfyUI in-chat

Loopback-only and manual-start by default. Sharing to your own devices is an explicit Tailscale opt-in. It never binds to your LAN.

Install

Three ways in. Pick your comfort level.

You need Windows 11 with an NVIDIA GPU and Docker Desktop. The installer picks models that fit your hardware (see capability tiers).

Easiest: no typing

Download Install Local AI.cmd from the latest release and double-click it. Windows shows a security box because the file was downloaded; choose More info → Run anyway. The installer vets your GPU, picks fitting models, and opens your chat at 127.0.0.1:3000.

Download installer
# After it finishes, start/stop with no typing:
Start Local AI.cmd
Stop Local AI.cmd

# They live in %USERPROFILE%\localai

Guided installer (the Friend Bootstrapper)

Vets your hardware, picks fitting models, brings the stack up loopback-only, then hands off to health checks. The bootstrap is pinned and fails closed: it verifies the download against a released tag's commit SHA (or zip SHA-256) before running anything.

# In Windows PowerShell: download, then run the pinned bootstrap.
Invoke-WebRequest https://raw.githubusercontent.com/allusionsafk/localai-windows-starter/master/installer/bootstrap.ps1 -OutFile "$env:TEMP\localai-bootstrap.ps1"
powershell -ExecutionPolicy Bypass -File "$env:TEMP\localai-bootstrap.ps1"

Manual bring-up

For when you already have the repo checked out and want each step explicit. Requires Python 3.12+.

pip install -e .
copy .env.example .env        # then set SEARXNG_SECRET to a long random string
localai start                 # Ollama (native) + the compose services
localai health                # end-to-end checks
# open http://localhost:3000 and create your admin account on first visit

On your phone

Your AI in your pocket. The GPU stays home.

iPhone or Android, same chat. Tailscale links your phone to your PC over an encrypted private network, so the stack keeps running on your desk while you use it from anywhere.

  1. Publish from the PC, once

    Run localai anywhere --apply. It uses Tailscale Serve to put your chat on your private tailnet over HTTPS. No Tailscale yet? localai anywhere --install-tailscale sets it up first.

  2. Put Tailscale on the phone

    Install the Tailscale app from the App Store or Google Play and sign in to the same tailnet as the PC. That's the whole pairing step.

  3. Open your private URL

    Visit https://your-pc.your-tailnet.ts.net in Safari or Chrome. Use Add to Home Screen and the chat opens full-screen like a native app.

  4. Chat from anywhere

    Home Wi-Fi, campus, LTE. It works wherever the phone has internet, as long as the PC at home is awake with the stack started.

# On the Windows PC (one time):
localai anywhere --install-tailscale  # only if Tailscale is missing
localai anywhere --apply              # publish chat to your tailnet
localai anywhere                      # re-check status any time

# On the phone: install Tailscale, sign in,
# then open your URL:
https://your-pc.your-tailnet.ts.net

Honest notes

  • Tailnet-only. The URL works only for devices signed into your own Tailscale network. It is never published to the open internet.
  • Encrypted end to end. Phone-to-PC traffic runs inside WireGuard tunnels.
  • The phone stays cool. Generation happens on your GPU at home; the phone just renders the page.
  • Off is one command. tailscale serve reset stops the sharing, and stopping the stack does too.

See more: the Arduino room sensor that talks to the stack

A pocket-money ESP8266 board watches indoor and outdoor climate and serves its own tiny dashboard. It runs perfectly with the AI stack off. When the stack comes up, the board notices and upgrades itself.

  • LOCAL CORE, always. Deterministic readings and a prioritized next action, computed on the board. No AI required, ever.
  • AI ENHANCED, when offered. A lightweight capability probe detects Ollama and adds a locally generated room-voice line. Stop the stack and it falls back cleanly.
  • Local news briefing. The dashboard embeds a sandboxed SearXNG frame with direct results, labeled plainly as not AI-summarized.
  • Fail-closed firmware. Filesystem autoformat is disabled, and the firmware has no code path that can start anything on the PC.
  • One-hole firewall. The PC allows exactly one sensor address to reach Ollama; every other local AI port stays blocked on physical networks, and localai firewall audits that this stays true.

Security contract

Local-first, and locked down by default.

  • No network exposure by default. Every port binds to 127.0.0.1. No raw LAN or 0.0.0.0 binds.
  • No autostart. No scheduled tasks, no Docker restart policies, no auto-launch. Starting the stack is always a manual choice.
  • Secrets stay local. .env is gitignored; you generate your own SEARXNG_SECRET.
  • First account = admin. Stored only in the local database on your PC.
  • Sharing is an explicit opt-in. Reach it from your phone via Tailscale Serve, private to your tailnet and never public.

Capability tiers

It sizes the model to your card.

VRAM is the binding limit. Assuming a q8_0 KV cache host-side, each tier's ceiling model stays on the GPU. Pick your VRAM to see the fit.

Honest tradeoff: large context and large models can still spill to CPU when VRAM is insufficient, which slows generation. localai model-scout shows the picks and the tradeoffs for your box.

Troubleshooting

The usual first-run snags.

Windows blocks the installer

SmartScreen shows a security box because the file was downloaded; click More info → Run anyway. If there is no "Run anyway" option at all, Smart App Control is on and blocks unsigned scripts outright. Turn it off under Windows Security → App & browser control, or use the PowerShell install method.

Docker Desktop needs one launch first

If setup can't reach Docker, open Docker Desktop once and let it finish starting, then re-run the installer.

My GPU is AMD or Intel

This stack is NVIDIA/CUDA-only. On AMD or Intel it runs CPU-only and is slow; the installer says so plainly instead of pretending otherwise. See the CPU tier.

What hardware is planned next?

The current download still supports Windows 11 with NVIDIA CUDA. After Windows v1, an Apple Silicon M4 pilot comes first, using native Ollama with Metal acceleration and model fitting based on unified memory. Later validation includes native Windows and Linux ARM64, Windows NPUs from Intel, AMD, and Qualcomm through verified runtime providers, and NVIDIA DGX Spark as a Linux ARM64 and CUDA stretch target. NPU support is an evaluation path, not a claim that the current Ollama stack uses it. Each platform stays planned until the full install, Scout, Prepare, update, backup, recovery, and uninstall flow passes on real hardware.

First chat is slow / no model loaded

Cold-loading a model reads it off disk into VRAM. The installer picks a model that fits your card; use localai warm to preload, or localai model-scout to choose a lighter one.
